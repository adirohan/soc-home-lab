# 06. Windows Security Monitoring

This section documents Windows security auditing and the monitoring of security-relevant activity from the Windows endpoint (SOC-WIN01).

The objective was to enable Windows security auditing, generate controlled activity, and verify that the resulting security events were visible through Wazuh.

---

## 06.1 Windows Audit Policy Configuration

Windows auditing was configured on the endpoint to generate security telemetry that can be collected and monitored by Wazuh.

The following audit categories were enabled from an elevated PowerShell session:

    auditpol /set /category:"Logon/Logoff" /success:enable /failure:enable
    auditpol /set /category:"Account Management" /success:enable /failure:enable
    auditpol /set /subcategory:"Process Creation" /success:enable /failure:enable

Process creation auditing was also configured to include command-line information:

    reg add "HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System\Audit" /v ProcessCreationIncludeCmdLine_Enabled /t REG_DWORD /d 1 /f

These settings allow Windows to generate security events related to authentication, account management, and process execution.

## 06.2 Controlled User Account Activity

To generate account-management telemetry, a test local user account was created on the Windows endpoint.

The following command was executed from an elevated PowerShell session:

    net user SOC-TestUser "TestUserPassword123!" /add

The command completed successfully and created the test account.

This was performed as a controlled lab activity to verify that Windows account-management events could be observed by the monitoring system.

---

## 06.3 Wazuh Detection of Account Activity

After the test account was created, the Wazuh Threat Hunting Events view was checked for the resulting security events.

Wazuh detected the account activity generated by the Windows endpoint.

The observed events included:

- Rule Description: User account enabled or created
- Rule ID: 60109
- Rule Level: 8
- Agent: SOC-WIN01

A related account-change event was also observed:

- Rule Description: User account changed
- Rule ID: 60110
- Rule Level: 8
- Agent: SOC-WIN01

## 06.4 Why Windows Security Monitoring Matters

Windows generates a large amount of security telemetry that can help a SOC analyst understand what is happening on an endpoint.

Security monitoring can provide visibility into activities such as:

- User logons and logon failures
- User account creation and modification
- Privilege-related activity
- Process creation
- Other Windows security events

These events can be collected by Wazuh and used during alert investigation and threat detection.

For example, unexpected account creation may be suspicious because an attacker could create or modify accounts to maintain access to a compromised system.

However, the presence of an event alone does not prove malicious activity. A SOC analyst must consider the user, process, timing, source, and surrounding events before deciding whether activity is suspicious.

---

## 06.5 Detection Workflow

The activity performed in this lab followed the following monitoring workflow:

Windows Audit Policy → Controlled Activity → Windows Security Event → Wazuh Collection → Rule Detection → SOC Investigation

## 06.6 SOC Analyst Takeaway

This exercise demonstrated how Windows security auditing can be used to generate useful endpoint telemetry and how Wazuh can collect and detect that activity.

The lab also provided practical experience with:

- Windows auditpol
- Windows Security auditing
- Account Management events
- Process Creation auditing
- Controlled user account creation
- Wazuh event monitoring
- Wazuh rule identification
- Basic SOC event analysis

The key lesson is that effective SOC monitoring depends on both generating the right endpoint telemetry and having the monitoring platform correctly collect and interpret that telemetry.
